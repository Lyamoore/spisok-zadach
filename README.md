# Список задач

Небольшое приложение на React, TypeScript, Vite и Material UI. Задачи хранятся в браузере и остаются после обновления страницы.

Сайт: https://lyamoore.github.io/spisok-zadach/

## Запуск

```bash
pnpm install
pnpm dev
```

Проверка:

```bash
pnpm build
pnpm lint
```

## Инструменты

- ChatGPT 6 Luna — составление промпта.
- Cursor, Grok 4.7 — код, интерфейс и проверка приложения.

## Промпт

```text
Ты — опытный frontend-разработчик уровня senior/middle с хорошим чувством визуального дизайна. Создай с нуля в текущей рабочей папке полностью готовое к запуску приложение «Список задач» на русском языке.

Считай, что существующего проекта нет: создай структуру, конфигурацию, зависимости и исходный код. Не ограничивайся планом или примером — реализуй приложение целиком.

## Технологии

- React и TypeScript.
- Vite для сборки и локального запуска.
- Material UI для компонентов, темы и адаптивной стилизации.
- Используй pnpm и создай lock-файл.

## Функциональность

1. Пользователь может добавить задачу.
   - У задачи есть уникальный идентификатор и текст.
   - Удаляй пробелы в начале и конце текста.
   - Не разрешай добавлять пустую задачу.
   - Форма отправляется по Enter и нажатию кнопки.
2. Пользователь может отметить задачу выполненной и вернуть её в активное состояние.
3. Пользователь может переместить задачу из основного списка в архив.
4. Пользователь может открыть архив и восстановить задачу.
5. Задачи сохраняются после обновления страницы с помощью `localStorage`.
6. При восстановлении задача сохраняет свой статус выполнения.

## Модель и хранение

Используй простую модель задачи, например: `id`, `title`, `completed`, `createdAt`, `archivedAt`.

Архив — это мягкое удаление: архивная задача остаётся в хранилище и исчезает из основного списка, пока пользователь её не восстановит. Не удаляй задачу окончательно при перемещении в архив.

Изолируй операции с задачами и чтение/запись `localStorage` от компонентов интерфейса. Обрабатывай ошибки чтения, записи и некорректные сохранённые данные: приложение не должно падать или молча затирать повреждённые данные.

## Дизайн

Сделай минималистичный тёмный интерфейс, вдохновлённый сдержанностью и вниманием к деталям в продуктах Apple, но не копируй конкретный экран или продукт.

Визуальное направление:

- почти чёрный или глубокий графитовый фон;
- немного более светлые поверхности карточек и элементов списка;
- белый и мягкий серый для текста, один сдержанный акцентный цвет;
- крупный и ясный заголовок, аккуратная типографика и достаточно свободного пространства;
- тонкие разделители, мягкие скругления и деликатные состояния наведения;
- без ярких градиентов, тяжёлых теней, визуального шума и стандартного вида «админ-панели».

Используй тему Material UI и системный стек шрифтов, чтобы не зависеть от внешней загрузки шрифтов. Настрой контраст, фокус и состояния кнопок так, чтобы интерфейс оставался читаемым и доступным.

## Интерфейс приложения

- Заголовок приложения и аккуратная форма добавления задачи.
- Переключение между разделами «Задачи» и «Архив».
- Фильтры списка задач: «Все», «Активные», «Выполненные».
- Строка задачи с checkbox, текстом и понятным действием перемещения в архив.
- В архиве у каждой задачи есть действие восстановления.
- Показывай количество задач там, где это помогает ориентироваться.
- Добавь отдельные пустые состояния для пустого списка, результатов фильтра и пустого архива.
- Сделай адаптивную компоновку для мобильного экрана.
- Добавь доступные подписи для кнопок с иконками и видимый клавиатурный фокус.
- Все пользовательские тексты интерфейса должны быть на русском языке.

## Критерии готовности

Убедись, что реализованы сценарии:

- добавить задачу и увидеть её в списке;
- запретить отправку пустого или состоящего из пробелов текста;
- отметить задачу выполненной и снова сделать её активной;
- обновить страницу и увидеть ранее сохранённые задачи;
- переместить задачу в архив;
- восстановить задачу из архива с прежним статусом;
- пользоваться списком и архивом на мобильном экране.

Проверь проект доступными командами сборки и проверки кода, если они настроены. Не добавляй тестовый фреймворк ради этой задачи.
```
